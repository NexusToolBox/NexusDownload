# NexusDownload 设计规范（定稿）

2026-11-15。本目录是客户端与官网的**唯一视觉依据**：

| 文件 | 用途 |
|---|---|
| `client.html` | 客户端高保真样稿：下载、网盘、媒体、服务、设置五个页面，浅色/深色，添加栏预检卡（点添加栏或按 Ctrl+K），空列表状态 |
| `website.html` | 官网首页样稿，含桌面与手机适配 |
| `tokens.css` | 颜色、字体、间距、圆角、阴影变量，客户端和官网共用 |
| `icons/app-icon.svg` | 应用图标母版 |
| `icons/tray-*.svg` | 托盘图标：浅色/深色任务栏 × 空闲/下载中/出错 |

实现时以样稿的实际渲染为准；本文解释样稿背后的规则，样稿没画到的界面按这些规则推导。

## 1. 设计主张

**一句话：保留 Motrix 让人舒服的骨架，换掉它的装饰，用“汇流”建立自己的识别度。**

1. **骨架继承 Motrix。** 浅灰窗口底色上浮起一块白色内容面板，左侧是无边框侧栏；页面标题大而粗；工具按钮和状态都用胶囊形。这是用户喜欢 Motrix 的原因，保留。
2. **装饰全部换掉。** 去掉 Motrix 的彩色 3D 设置图标、像素渐变空状态、兔子/乌龟限速图标、macOS 红绿灯。改为 Windows 原生位置的窗口按钮、单色线性图标、无插画的空状态。
3. **颜色只给“正在流动”的东西。** 品牌色“汇流青”只出现在：进度条、实时速度、正在执行的处理步骤、续链中的提示。选中、按钮、开关、标签一律用中性色（主按钮是近黑色胶囊）。这样打开窗口一眼就能看出哪些任务在动，界面整体安静。
4. **品牌意象是“汇流”。** 多股来源汇成一点再落下：应用图标、官网首屏的光线动画、托盘图标是同一个图形的不同尺寸版本。

之前 Codex 方案的问题在这里记一笔，避免重犯：三个方向都是同一套后台模板换三种蓝色；字号普遍 12px 以下、信息挤；丢掉了 Motrix 的浮起面板和大标题；图标是一个普通的“N”；官网首屏是通用 SaaS 构图。

## 2. 设计变量

全部定义在 `tokens.css`。客户端实现时**不新建变量体系**，而是把值填进底座 `src/renderer/styles/globals.css` 已有的 shadcn 语义变量：

| 底座变量 | 填入 | 说明 |
|---|---|---|
| `--sidebar` | `--shell` | 窗口底色与侧栏 |
| `--sidebar-accent` / `--sidebar-active` | `--shell-2` | 侧栏选中 |
| `--background` / `--card` | `--panel` | 内容面板 |
| `--muted` / `--accent` | `--panel-2` 或 `--panel-3` | 悬停、输入框底 |
| `--border` | `--line` | 分隔线 |
| `--foreground` | `--text` | 正文 |
| `--muted-foreground` | `--text-2` / `--text-3` | 次要、辅助文字 |
| `--primary` / `--primary-foreground` | `--ink` / `--ink-text` | 主按钮、开关打开 |
| `--ring` | `--live` | 键盘焦点环 |
| `--destructive` | `--red` | 出错 |
| `--radius` | `14px` | 底座的 sm/md/xl 由它推导，内容面板为 14px |
| 新增 `--live`、`--live-strong`、`--live-soft` | 同名 | 底座没有，新增三项即可 |

浅色和深色两套值都在 `tokens.css`，深色不是浅色的反相：深色下内容面板比窗口底色**更亮**一级，与浅色的层级关系一致。

## 3. 字体

| 用途 | 字体 | 获取方式 |
|---|---|---|
| 拉丁字母与数字 | Geist（可变字重） | npm `@fontsource-variable/geist`，随应用打包 |
| 中文 | 思源黑体 Noto Sans SC 400/500/700 | npm `@fontsource/noto-sans-sc`，随应用打包 |
| 官网首屏标题（仅此一处） | 思源宋体 Noto Serif SC 900 | npm `@fontsource/noto-serif-sc`，只引入 900 |

字体栈写成 `"Geist Variable", "Noto Sans SC", "Microsoft YaHei UI", sans-serif`：英文和数字走 Geist，中文自动落到思源黑体。所有数字开启等宽数字（`font-variant-numeric: tabular-nums`），速度和百分比跳动时不抖。三套字体都是 SIL OFL 开源许可，可以随软件分发。

客户端字号阶梯：

| 级别 | 字号/字重 | 用在哪里 |
|---|---|---|
| 页面标题 | 28px / 700，字距 -0.02em | 每页左上“下载”“网盘”等 |
| 对话框标题 | 20px / 650 | 预检卡标题为 18px |
| 分组标题 | 15px / 600 | 设置分组、服务分组 |
| 列表主文字 | 14px / 500 | 任务名、侧栏导航 |
| 正文 | 13.5px / 400 | 表单、说明 |
| 辅助信息 | 12.5px / 400 | 大小、剩余时间、路径 |
| 标签 | 11.5px / 500 | 来源标签 |

**最小字号 11.5px，只用于标签。** 正文不得小于 13px。

## 5. 关键组件规则

**任务行。** 第一行是文件名，第二行依次是来源标签、大小、补充说明（如“免转存”“完成后解压”）。进度不放在单独的列里，而是一条 3px 的“水位线”横贯在行底部，从名称起点到行尾。下载中的水位线是汇流青并带缓慢流光；暂停为灰色；出错为红色；已完成的行不显示水位线，只在百分比位置显示绿色对勾。行内操作按钮平时隐藏，悬停或选中时出现。

**排序与分组。** “需要处理”的任务（出错、等待登录、续链中）永远排在最前面。下面依次是进行中的任务、按队列分组的等待任务（分组标题如“夜间队列 · 23:00 开始”）、今天完成的任务。

**包。** 分享目录、分卷压缩和播放列表显示为一行“包”，图标底色带一点星蓝以示区别，点击展开子文件。子文件缩进 48px，左侧有一条竖线，行高 44px。

**详情栏。** 自上而下依次是：文件名（标明“原文件，非转码”或“播放流”）、40px 大号百分比加进度条、实时速度与速度曲线、事实表（来源、账号、取链方式、路线、保存位置）、处理阶段（竖向步骤：已完成为实心黑点，正在进行为青色圆点，未开始为空心圆）、底部的主操作按钮。

**预检卡。** 点击添加栏、按 Ctrl+K 或粘贴链接后，从添加栏下方弹出，宽 560px，圆角 16px，背后的面板蒙上一层浅色。内容依次为：输入原文、平台、标题、文件数与总大小、两列检查结果（绿色对勾表示通过，琥珀色感叹号表示需要注意）、底部的保存位置和两个按钮。按钮文字写明结果，例如“下载 20 个文件”。Esc 关闭。

**空状态。** 没有任务时，列表区居中显示汇流图形（单色线稿 64px）、一句行动标题“粘贴一个链接开始下载”、一句说明，以及可识别的来源标签和“添加下载”按钮。不使用插画。样稿顶部的“空列表”按钮可以预览。

**详情栏的操作按钮固定在底部**，内容超出高度时只滚动上方区域，暂停按钮始终可见。

**滚动条。** 使用 10px 细滚动条：平时透明，鼠标移入区域才显示；不使用 Windows 默认的粗滚动条。

**状态色语义：**

| 状态 | 颜色 | 表现 |
|---|---|---|
| 下载中、续链中、正在处理 | 汇流青 `--live` | 水位线、速度数字、步骤圆点 |
| 暂停、等待 | `--text-3` 灰 | 灰色水位线，文字写“等待”或“已暂停” |
| 需要注意（文件已存在、离线） | 琥珀 `--amber` | 只用于小圆点和图标 |
| 出错 | 红 `--red` | 红色水位线和红色标签，并写明原因与解决办法 |
| 完成 | 绿 `--green` | 只用于对勾图标，不给整行染色 |

**动效。** 悬停和按下 140ms，面板与弹层 220ms，曲线 `cubic-bezier(.2,.7,.2,1)`。水位线流光是唯一的常驻动画，系统开启“减少动画”时关闭。不使用毛玻璃，Windows 上不稳定也费电。

## 7. 文案规则

- 用用户能听懂的结果描述，不用实现术语。写“直链已过期，正在续链”，不写“403，changeUri”；写“可免转存下载”，不写“getShareDownloadLinkWithoutSave”。
- 按钮写明会发生什么：“下载 20 个文件”“检测这个账号”“加入夜间队列”。同一个动作前后用同一个词。
- 出错要说明发生了什么、怎么解决，例如“登录已失效，点击重新登录”。不道歉，也不写“出错了”这种空话。
- 空状态给出下一步操作，例如“粘贴一个链接开始下载”，不配插画。
- 句末不加句号的场景：按钮、标签、列表项。说明句加句号。

### 7.1 文字密度：能不写就不写

语气以 Windows 设置和 macOS 系统设置为标准：专业、克制、简短。既不用开发术语，也不用口语（不写“它自己接上”“放心”这类说法）。

判断一段文字该不该出现，按顺序问三个问题：

1. **它会改变用户的下一步操作吗？** 不会就删。例如“最近风控：暂无本机记录”“平台今日流量：未知”，状态正常或未知时不显示，只有出现异常才出现。
2. **标题已经说清楚了吗？** 说清楚了就不加副标题。例如“自动解压”下面不需要再写“下载完成后自动解压压缩包”。
3. **用户需要每次都看到它吗？** 只在第一次需要的说明，放进标题旁的 ⓘ 悬停提示或“了解更多”，不常驻在界面上。

长度上限：标签不超过 6 个字；副标题一行，不超过 16 个字；一个面板内常驻的说明文字不超过两句。

**正常状态不说话。** 健康、就绪、已连接这类正常状态，只用一个小绿点或一个数字表示；出现问题时才展开成文字，并附带解决按钮。

**未开放的功能不展示。** 不要出现“v0.4 开放”“v0.2 开放”这类开发进度提示。还没做的入口直接隐藏；必须占位的，置灰并在悬停提示里写“即将推出”。

**设置与查看分开。** 侧栏、详情栏只用于查看状态。备注、转存专用号这类设置项，放进点“编辑”才打开的对话框，不要直接铺在面板里。

**（v1.4 收紧）** 副标题上限改为 12 个字，并且只在“不看就会做错”时才写。不解释原理、不说明“怎么实现的”和“有多安全”（加密、校验、限流照做，不用告诉用户），界面上不出现 GitHub、哈希、Cookie、令牌、接口等词。页面标题、分组标题、行标题不重复同一个词；同一提示在同一屏只出现一次。错误信息一句话加一个解决按钮，不超过 15 个字。用不了的按钮和选项不显示。能自动做的不让用户选，不常用的设置收进各页底部默认折叠的“高级”分组。

### 7.2 用词表

界面上统一使用左列的词。右列的词只能出现在代码和日志里。

| 界面用词 | 不要出现在界面上 |
|---|---|
| 下载地址 | 直链、取链 |
| 获取下载地址 | 取链、解析直链 |
| 地址已过期，正在重新获取 | 续链、changeUri、403 |
| 无需转存 | 免转存 |
| 无需登录 | 游客、游客取链 |
| 请求频率限制 | 安全阀、AccountGovernor |
| 账号异常，已暂停 | 风控、触发风控 |
| 临时文件 | 临时转存残留 |
| 下载服务正常 | 引擎就绪、aria2 |
| 原文件 / 在线播放版本 | 原文件 / 非原文件、转码流、HLS |
| 本机下载 | 本机直连、路线 |
| 下载方式 | 路线、RoutePlan |

“转存”“提取码”“分享链接”“磁力链接”是网盘和下载工具的通用词，用户熟悉，可以保留。

## 8. 图标与系统入口（只考虑 Windows）

| 位置 | 用哪个版本 | 原因 |
|---|---|---|
| 应用图标（exe、开始菜单、任务栏、Alt+Tab） | `app-icon.svg` 完整版，导出 16/20/24/32/40/48/64/256 多尺寸 ico | 深色底块保证在浅色和深色桌面上都清楚 |
| 窗口左上角品牌 | 完整版 24px + 文字 | 与任务栏一致 |
| 系统托盘 | `tray-*` 单色线稿，按任务栏明暗切换 | 托盘图标约 16px，底块会糊成一团；单色线稿更清楚，也符合 Windows 11 托盘习惯 |
| 托盘状态 | 右下角圆点：青色表示下载中，红色表示有任务出错，无圆点表示空闲 | 不改变主图形，只加状态点 |
| 任务栏按钮进度 | 使用 Windows 原生任务栏进度条（Electron `setProgressBar`） | 系统自带，不用自己画 |
| 通知 | 完整版图标 | 系统通知会显示应用图标 |
| 官网浏览器图标 | 完整版 | 同一识别 |

导出 ico 时，16px 和 20px 两个尺寸需要单独微调：去掉节点光晕，线宽加粗到约 1.5px 实际像素。

**托盘右键菜单**，从上到下：

1. 当前状态（不可点）：“3 个下载中，52 MB/s”
2. 显示主窗口
3. 新建下载…（打开主窗口并聚焦添加栏）
4. 分隔线
5. 全部暂停 / 全部继续（按当前状态显示其中一个）
6. 速度模式 ▸ 常规 / 限速 / 自动
7. 分隔线
8. 退出（有任务正在下载时弹出二次确认，并写明“退出后 3 个下载会暂停”）

左键单击托盘图标显示或隐藏主窗口。关闭主窗口时默认最小化到托盘，首次关闭时提示一次。

**悬浮球：首版不做。** 任务栏原生进度条和托盘状态点已经能在不打开窗口时看到进度；悬浮球在全屏游戏和多显示器下问题多，还会暴露正在下载的文件名。如果以后要做，做成可选的“迷你速度条”：默认关闭；只显示总速度和下载中的数量，不显示文件名；可拖动并记住位置；全屏程序运行时自动隐藏。

## 9. 官网

**结构（一页完成首发）**：首屏 → 界面展示 → 三项能力（网盘、续链、整理）→ 隐私说明 → 下载区 → 页脚。顶部导航只有四个锚点。以后要扩展时，再加“更新记录”“使用说明”两个独立页面。

**首屏**是全站唯一着重设计的地方：黑底，六股带来源标签的光线从上方汇入一点，再落向标题。动画只在页面加载时完整播放一次，之后只有零星的光点沿线流动；系统开启“减少动画”时显示静态画面。标题使用思源宋体 900，全站只有这一处使用衬线字体。

**界面展示**直接嵌入客户端样稿（上线时换成真实截图，浅色一张即可）。

**托管**（2026-11-15 查询）：

| | 首选：Cloudflare Pages | 备选：GitHub Pages |
|---|---|---|
| 费用与流量 | 免费，静态请求与流量不限 | 免费，每月软上限 100 GB |
| 自定义域名 | 支持，免费 HTTPS；裸域名需要把域名的 DNS 托管到 Cloudflare | 支持，免费 HTTPS |
| 限制 | 每月 500 次构建，单文件不超过 25 MiB | 站点不超过 1 GB；使用政策排除商业用途 |

由于单文件上限是 25 MiB，**安装包不放在官网托管上**，下载按钮指向 GitHub Releases 的 ZIP 文件。两个平台在中国大陆访问都可能偏慢；要在国内加速，需要备案后接入国内 CDN，等访问量上来再考虑。

上线流程：官网放在仓库的 `website/` 目录 → 在 Cloudflare Pages 连接这个 GitHub 仓库，构建目录设为 `website` → 在 Cloudflare 里添加你的域名 → 以后每次推送代码自动更新。

## 10. 可访问性底线

所有可点击元素都要有可见的键盘焦点环（汇流青 2px）。正文与背景对比度至少 4.5:1；`--text-3` 只用于辅助信息，不能用来写关键内容。状态不能只靠颜色区分，同时要有文字或图标。支持 Windows 显示缩放 100% 至 200%。
